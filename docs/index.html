Some jobs never touch the model

The same tools run from your shell at zero tokens, piped through grep or jq before anything reaches the context. Pair session_record with replay for smoke tests with no model in the loop.

chrome-bridge navigate --url https://example.com
chrome-bridge read_console --level error | head -20
chrome-bridge assert --selector "#success" --text "Done"
chrome-bridge replay --file ./recordings/login.jsonl

Launch mode gives you a dedicated Chromium with an ephemeral profile, for isolated sessions or CI: node server/index.js --launch --headless.

Install it in three steps

Requires Node.js 18+ and Chrome 135+.

  1. Install the extension from the Chrome Web Store. 
    git clone git@github.com:frsorrentino/chrome-bridge.git
cd chrome-bridge && ./install.sh
  2. Restart Claude Code. install.sh registers the MCP server with --scope user; by hand it is claude mcp add --scope user chrome-bridge node /path/to/server/index.js.
  3. Ask for something real: “open localhost:3000, run an accessibility audit and find the Sign Up button”.

Without a clone: in Claude Code, /plugin install chrome-bridge --marketplace frsorrentino/chrome-bridge (one command, Claude Code 2.1.275+; on older versions /plugin marketplace add frsorrentino/chrome-bridge then /plugin install chrome-bridge@chrome-bridge) registers the MCP server from npm (all capabilities) together with the recipes skill. The extension still comes from the Web Store. Pick one path: the plugin and install.sh would register the same server twice, and so would a plugin added from the Anthropic directory on claude.ai next to a marketplace install. In claude.ai chat the plugin loads only the recipes skill: the tools need Claude Code, or Cowork running on your computer.

On ChromeOS/Crostini install from the Web Store rather than Load unpacked: an unpacked extension is dropped on every reboot, because the container is not mounted when Chrome starts.

What it does not protect

The bridge binds loopback, accepts connections only from a chrome-extension:// origin, and requires a token on both handshakes when one is set. Beyond that, be deliberate:

Page content is untrusted

Whatever a page says reaches the model unfiltered. A hostile page’s text is input, never instructions.

Exports are not redacted

get_storage, fixtures, HAR exports and screenshots may carry cookies, tokens or personal data.

Two switches worth knowing

--no-js refuses arbitrary JavaScript in the page; --write-root confines every path the model chooses.
